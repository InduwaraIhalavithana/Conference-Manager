# Security checklist (OWASP Top 10, 2021)

How ConferenceHub v3 handles each OWASP Top 10 risk. Every phase PR updates the rows it touched and says so in its description.
Status: **done** = built and tested; **planned** = the phase that delivers it.

| # | Risk | How v3 handles it | Status | Tests |
|---|---|---|---|---|
| A01 | Broken access control | Every GraphQL resolver gets the viewer from the server-side session; sign-in-only mutations return `NOT_AUTHENTICATED` otherwise. Suspended organizers and revoked sessions count as signed out immediately (the session is checked on every request). Only organizers create conferences and upload images; an organizer can only read or change **their own** conferences, and someone else's conference answers exactly like a missing one (`NOT_FOUND`), so ids reveal nothing. Drafts and admin-hidden conferences never appear publicly; public organizer data is name and organization only. Attendee names and emails are visible only to the conference's owner; a ticket at another conference's desk is refused. In the web app, the proxy sends signed-out visitors away from `/dashboard` and `/admin` (it only checks that a session cookie exists; the API still decides every request), and a profile photo must be an image this server stored in the avatars folder. | done | `test_change_password_needs_sign_in`, `test_suspended_organizer_is_refused_and_signed_out`, `test_only_organizers_create_and_only_owners_change`, `test_hidden_and_ended_conferences_are_not_listed`, `test_only_the_owner_sees_attendees_and_checks_in`, `test_notifications_are_paged_counted_and_marked_read` (nobody reads or marks another person's), `test_profile_rejects_bad_input_and_foreign_images`, `e2e/organizer.spec.ts` |
| A02 | Cryptographic failures | Passwords hashed with Argon2id (pwdlib); v2 PBKDF2 hashes upgraded at the next sign-in. Email codes and reset tokens stored only as HMAC/SHA-256. Tokens signed with HS256 and a required 32+ character `SECRET_KEY` (placeholders refused at start). Cookies `Secure` in production (start-up refuses otherwise). | done | `test_core.py`, `test_admin_password_is_only_stored_as_a_hash`, `test_forgot_and_reset_password_signs_out_everywhere` |
| A03 | Injection | MongoDB queries are built from typed values through Beanie, never from strings; GraphQL arguments are typed by the schema; input validated with Pydantic in the service layer. Search text is capped at 100 characters and only used as a `$text` search; the city filter is regex-escaped; URLs must be `http(s)://` (no `javascript:`); image fields only accept paths of files this server stored. Emails are rendered with Jinja2 auto-escaping, so a name like `<b>x</b>` arrives as text; email headers are built by Python's email library. The attendee CSV prefixes cells starting with `=`, `+`, `-` or `@` so spreadsheets never run them as formulas. | done | `test_create_rejects_bad_input`, `test_image_fields_only_accept_our_own_uploads`, `test_every_email_kind_renders_in_every_language`, `test_attendee_csv_is_owner_only_and_safe_in_excel` |
| A04 | Insecure design | Business rules live in `app/services` with an enforced layer order (import-linter). Answers to "resend code" and "forgot password" do not reveal whether an email is registered; wrong email and wrong password give the same error, after the same hashing time. **Seat limits:** a seat is taken by one atomic conditional increment inside a MongoDB transaction, so a conference cannot be overbooked even under a burst of sign-ups; counters can be recounted from the registrations; conference saves never write the counters back. Re-registering with the same email emails the ticket link instead of showing it. | done | `test_unknown_email_looks_like_a_wrong_code`, `test_login_wrong_password_and_unknown_email_look_the_same`, `test_concurrent_registrations_never_overbook` (200 people, 25 seats), `test_the_same_email_at_the_same_moment_registers_once`, `test_concurrent_cancellations_promote_exactly_as_many` |
| A05 | Security misconfiguration | No defaults for secrets; GraphiQL, `/docs` and GraphQL introspection are off in production; query depth, token and alias limits; CORS allow-list. The web app sends a Content Security Policy (no third-party scripts; images only from this site and OpenStreetMap tiles; `frame-ancestors 'none'`, `object-src 'none'`), `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, a `Permissions-Policy` that allows only geolocation and the camera, `Cross-Origin-Opener-Policy`, and HSTS in production; the `X-Powered-By` header is off. Scripts keep `'unsafe-inline'` because pages are pre-rendered and cached (a per-request nonce would make every page dynamic). Private ticket pages are `noindex` and disallowed in `robots.txt`. | done | `test_queries_with_too_many_aliases_are_refused`, `e2e/public.spec.ts` (robots rules) |
| A06 | Vulnerable and outdated components | `pip-audit` (API) and `npm audit --omit=dev` (web) run in CI and fail on known vulnerabilities; Dependabot opens update PRs weekly; lockfiles (`uv.lock`, `package-lock.json`) pin exact versions. | done | CI jobs |
| A07 | Identification and authentication failures | Email verification by 6-digit code (15 minutes, 5 tries, resend once a minute); rate limits per IP on every sign-in, sign-up, code and reset mutation (Redis); short-lived access tokens (15 min) in httpOnly cookies; refresh tokens rotated on every use, and reusing an old one revokes the session; changing or resetting a password signs out other devices; CSRF double-submit header on every mutation. A readable `cm_who` cookie says only "organizer" or "admin" so the header can show the account menu; it grants nothing. When an access token expires, the web app refreshes once and retries the request. Organizers can sign out every other device from Settings. The public contact form is limited to 5 messages per 10 minutes per IP address. Behind the Next.js proxy the API sees the visitor's address through `X-Forwarded-For`, which uvicorn trusts only from `FORWARDED_ALLOW_IPS` (127.0.0.1 by default; set it to the proxy's address in production, Phase 8). Attendees have no account: their 12-character ticket code (31-letter alphabet, about 8 x 10^17 values) is the bearer key to their ticket and is only sent to their email; a seat is held until the emailed 6-digit code is entered. | done | `test_signing_out_clears_the_who_cookie`, `test_sign_out_other_devices_keeps_this_one`, `test_contact_form_is_stored_for_the_admin_and_rate_limited`, `test_auth.py` (refresh rotation and reuse, CSRF, rate limit, code lock-out) |
| A08 | Software and data integrity failures | Dependencies installed from lockfiles only (`uv sync --locked`, `npm ci`); CI must be green before merging. Uploads: JPG/PNG/WebP only, size limits, decompression-bomb limit, opened and verified by Pillow, then **re-encoded to WebP** so metadata (EXIF, GPS) and anything hidden in the original never reach disk; random file names; files outside the upload folder can never be referenced. Concurrent edits of a conference cannot silently overwrite each other (revision check). | done | `test_uploads.py`, `test_two_editors_cannot_overwrite_each_other` |
| A09 | Security logging and monitoring failures | Structured JSON logs with a request ID on every line and response; sign-ins, verifications, password changes and refresh-token reuse written to the activity log; Sentry for errors (no personal data sent). The worker logs every email it skips or gives up on after 3 tries, and the nightly recount logs any seat-counter drift it fixes. Passwords, tokens and codes are never logged (codes only by the local-development email stand-in). | done | `test_reusing_an_old_refresh_token_revokes_the_session` (activity entry) |
| A10 | Server-side request forgery | The API makes no requests to URLs supplied by users. Map tiles are fetched by the browser from OpenStreetMap; the web server only calls the API at its configured `API_URL` (server components, the sitemap and share images), never a URL taken from a request. | done (nothing to forge) | — |

## Accessibility (not OWASP, but checked the same way)

Every public page is scanned with axe (WCAG 2.2 AA rules) in light and dark themes, on desktop and a phone-sized screen; serious or critical problems fail CI (`e2e/a11y.spec.ts`). A keyboard test checks the skip link.

## Secrets

- `SECRET_KEY`, the admin password, SMTP credentials and the Sentry DSN only exist in git-ignored `.env` files or the host's environment.
- The admin password is never written in code, tests, seed scripts, docs, logs or chat. Tests use their own throw-away admin password in a throw-away database.
